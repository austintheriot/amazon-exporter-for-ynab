# Lit popup on a TEA core: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the popup as Lit light-DOM components driven by a pure TEA core, and add per-row checkboxes, unmatched-charge reasons, scan-to-budget binding, abortable runs, and background YNAB sign-in.

**Architecture:** `lib/core/popup/` holds `Model`, `Msg`, `Effect`, `update`, and `viewModel`, all pure and covered by the existing purity lint. `entrypoints/popup/runtime.ts` owns the model and runs effects through an injected `Services` bag built in `lib/shell/popup-services.ts`. Lit components render a `PopupView` and emit `msg` events. They never do IO.

**Tech Stack:** Bun 1.4.2, WXT 0.21, TypeScript 6.0.3, Vitest 4.1.11, zod/mini 4.6.7, fast-check, lit 3.3.3, happy-dom 20.14.6.

**Spec:** `docs/superpowers/specs/2026-10-27-lit-popup-design.md`

  - `type UnmatchedReason = { kind: 'digital' } | { kind: 'order-unreadable' } | { kind: 'already-has-memo' } | { kind: 'taken' } | { kind: 'outside-window'; daysAway: number; maxDays: number } | { kind: 'no-amount-match'; closest: { amount: number; date: string } | null }`

Reason algorithm for an entry with no proposal (identity: kind, orderId, date, amount, compared as a multiset):
1. Order ID starts `D0`: `digital`.
2. Entry is in `claimMatches` output: `order-unreadable`.
3. `sameAmount` = candidates with matching sign and exact amount (memo ignored). Empty: `no-amount-match`, `closest` = the sign-matching candidate with the smallest amount difference, ties to nearest date, or `null`.
4. `inWindow` = `sameAmount` filtered by `withinWindow`. Empty: `outside-window`, `daysAway` = smallest absolute day distance, rounded.
5. Every `inWindow` candidate has a memo: `already-has-memo`.
6. Otherwise: `taken`.

**Interfaces:**
- Produces in `services.ts`:

```ts
interface Services {
  clock: { nowIso(): string };
  boot: { read(): Promise<Omit<BootSnapshot, 'now'>> };
  watch(onMsg: (msg: Msg) => void): () => void; // emits syncStateChanged, settingsChanged, tokenChanged, ynabAuthChanged
  settings: { patch(patch: Partial<Settings>): Promise<void> };
  ynab: { loadBudgets(): Promise<YnabBudget[]>; disconnect(): Promise<void> };
  amazon: { requestPermission(): Promise<boolean>; openLogin(): Promise<void> };
  background: { send(message: Message): Promise<void> };
  files: { download(name: string, json: string): void };
  logger: { error(context: string, detail: string): void };
  ticker: { every(ms: number, onTick: () => void): () => void };
}
```

- Produces in `runtime.ts`: `createPopupRuntime(services: Services): { getModel(): Model; dispatch(msg: Msg): void; subscribe(listener: (model: Model) => void): () => void; dispose(): void }`. It calls `watch` before `boot.read`, queues watched messages until `booted`, then replays them in arrival order. It runs each effect and turns every rejection into `effectFailed`. It ticks every 30 000 ms with `clock.nowIso()`. `dispose` unsubscribes the watcher and the ticker.
- `popup-services.ts` builds the real `Services`: `boot.read` uses `getSettings`, `getState`, `isConnected`, `getYnabAuth`, `browser.permissions.contains({ origins: AMAZON_ORIGINS })`, `oauthConfigured()`. `watch` parses `changes[key].newValue` with the existing parsers for `syncState`, `settings`, `ynabAuth`, and maps `oauthToken` to `tokenChanged{ connected: newValue !== undefined }`. `settings.patch` reads, merges the patch, writes. `ynab.loadBudgets` gets a token with `getAccessToken()` and throws when null. `files.download` creates an object URL, clicks an anchor, and revokes the URL after 60 000 ms.

- `a stale budget reply does not replace a newer one`: two `tokenChanged` cycles; resolve the first `loadBudgets` last; budgets equal the second reply.
